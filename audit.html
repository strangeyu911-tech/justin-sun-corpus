站点审计报告

对「孙割这十年」的三页站点做一次自查：口径沿用「以日为镜」的五条写作纪律， 逐维度给出实测数据（不是形容词）、问题清单与处理状态，以及可以自己复跑的复核脚本。 审计对象是 3 个页面 / 46 个正文板块 / 313 个元素级结论，审计时点见页脚。

审计范围 3 页 正文板块 46 个 硬性结构缺陷 0 置信度标签 141 处 已修问题 5 项 有意保留 2 项 透明声明 3 项

这份审计要回答三个问题：① 排版与格式有没有硬伤（能不能正常看、正常读、正常检索）； ② 置信度标注是不是真的落到了每一条具体结论上（而不是只在页首喊一句口号）； ③ 哪些地方我知道自己还不足，且不打算用话术掩盖。第 ③ 条最要紧——它决定了这份报告是不是一份真的审计。

审计结论（速览）

编者自审结论由本站作者自查得出，不是第三方审计

先说判断，再说依据。

结论一

可以发布：硬性结构项 0 缺陷

24 类 HTML 标签全部平衡（差值 0）；三页无重复 id；目录与正文双向对齐（29/26、16/14，缺失 0、孤立 0）； 站内检索 47 条索引的锚点全部命中；行内样式已归零；图标按钮与纯图标链接100% 有可访问名称。

结论二

置信度做到了「逐条可核」，但密度低于「以日为镜」

46 个板块 100% 有来源徽章；50 条引语 100% 带出处标签（卷一 34 条、卷二 16 条）； 速览卡片与逐讲索引分组另有来源行。但段落中间没有逐句标注——这是有意保留的取舍，理由见 A4。

结论三

三处「标题 ≠ 内容」的坑已经查实并标注

最典型的是卷一第 010 分 P：标题写着《因信仰自由而享受自由》，但用本地 ASR 转写比对后确认 它的音频其实是《性与权力》，且与第 019 分 P 是同一集重复音频（开头逐字相同、相似度 0.85、时长差 5 秒）。 这类问题已经写进索引行内与页脚，没有藏起来。

结论四

三个「有意保留」的不足，不打算用话术盖过去

① 段落级逐句标注缺失；② 卷一速览 11 张卡片的讲号映射属编者判断； ③ 卷一 146–155 集只有二手 AI 概要、无法逐字核对。 三项都已在页面上显式声明并降档标注。

A2排版：版式、字体、深浅色

实测尺寸、断点与颜色变量均为代码实测值

排版维度看四件事：版心与留白是否稳定、字号与行高是否适合长文、宽屏与手机是否都成立、深色模式有没有残留。

版心与网格

版心 1240px，宽屏目录常驻 322px

内容列固定 --wrap-w:1240px；屏幕 ≥1119px 时左侧目录常驻 322px，正文与顶栏右列用同一条 calc(var(--toc-w) + max(0px, (100% - var(--toc-w) - var(--wrap-w))/2)) 计算，两者严格对齐。 小屏时该规则整体失效，退化为抽屉目录，正文回到单列居中。

竖向节奏

板块间距 56px，锚点偏移随顶栏自适应

section{margin-bottom:56px}；scroll-margin-top:calc(var(--bar-h) + 20px) 保证点击目录跳转时标题不被 sticky 顶栏遮住。顶栏高度统一为 --bar-h:58px，抽屉、搜索面板、 移动端搜索条的吸顶位置全部由这一个变量推导。

字体

正文无衬线、标题用宋体，均为系统字体栈

正文栈：PingFang SC → Hiragino Sans GB → Microsoft YaHei → Source Han Sans SC → system-ui； 标题栈：Songti SC → Source Han Serif SC → Noto Serif SC → Georgia。 不加载任何 Web 字体，因此没有字体造成的布局抖动（CLS），中文阅读观感也更接近纸面。

深浅色

所有颜色走 CSS 变量，硬编码浅色已全部覆盖

颜色令牌在 :root 与 html[data-theme="dark"] 两处定义，共 26 个变量， 深色下覆写 20 个（其余 6 个是尺寸与字体栈，本来就不需要覆写）。 原设计里三处硬编码浅色（引用块渐变底、警示卡底色与标题色、头部径向渐变）已单独加 dark 覆写， 切换后无浅底深字或深底浅字残留。主题选择写入 localStorage，并在 <head> 内联脚本里提前应用，避免闪白。

响应式

六档断点，手机端搜索框收成一个放大镜

断点 1119 / 760 / 680 / 480 / 400 / 360 px。480px 以下搜索框折叠为图标，点击后整行下拉； 400px 以下隐藏 GitHub 图标保留分享与主题；品牌名三档收缩（全称 → 简称 → 两字）。

正文行高 1.78（约 27.6px）。版心 1240px ÷ 15.5px ≈ 80 个字/行（按全角字宽估算）， 落在中文长文的舒适区。引语块用宋体 + 暖底，与正文形成明确层次。

A4置信度体系落地：三档、三个层级

体系说明语义改造的完整理由

置信度是这次改造的核心。它是「照搬以日为镜的做法」，但不是照抄它的语义——因为内容性质变了。

原话 · 已核字幕

可以当引用用有官方字幕或原视频逐字可核验，出处精确到讲号 / 时间码。

转写 · 中可信

引前须回原音依据第三方 ASR 转写或二手压缩材料，同音字、断句与专有名词都可能有误。

概要 · 待核

只能当线索别人已经压缩过一遍的概要，或标题 / 编号本身存疑、原片检索不到的流传说法。

为什么改语义

「以日为镜」标的是判断力，本站标的是引文保真度

那一站是作者自己的判断，所以标签问的是「这个结论有多可信」。 本站是转述别人的言论，对错不是编辑能担保的——编辑能担保的只有一件事：这行字离原话有多远。 所以三档的语义换成「保真度」，并且把「说错了」和「不是我说的」严格分开。

分层设计

板块徽章 → 卡片来源行 → 引语标签

① 板块级（40 处）：每个板块标题下一行来源徽章，写明依据与讲号 / 时间码区间。
② 卡片 / 索引级（约 40 处）：速览卡片与索引分组各有来源行。
③ 引语级（50 条）：每条逐字引语的出处行末尾挂标签，讲号落在哪个来源区间就标哪一档。

有意保留

段落中间不做逐句标注

「以日为镜」可以做逐句标注，因为它的每一句都是作者的判断，都要定级。 本站的正文是连续转述，如果给每句话都盖一个章，就会制造一种「逐句都核过了」的伪精度—— 而事实上同一段里的依据强度是一样的。

所以本站把定级放在段落所属的来源区间上，而不是每一句上。密度更低，但每一枚标签都是真的。

有意保留

卷一速览 11 张卡片：讲号映射属编者判断

速览卡片是面向「如果只读一段」的重写稿，讲号与卡片的对应关系是编者按内容判定的， 不是原文自带的。这些卡片已标为「已核字幕」并写明具体讲号，读者可以按讲号回听核对。 这一步是推断，不是转录——已知并标注。

交互验收

静态检查够不到的那一层：17 / 17 通过

标签配平、锚点存在、无行内样式——这些证明不了顶部栏那几样 JS 交互真的能用： 搜索会不会高亮、分享菜单会不会弹、日夜模式会不会切换并记住、抽屉目录能不能开。 而顶部栏正是本站照搬「以日为镜」的核心交付，只截图看不出来。

所以另有一份真交互验收：_build/accept.mjs 用 Playwright 驱动真实 Edge 浏览器跑 17 条断言，覆盖日夜模式切换 + localStorage 持久化、 检索命中数与无命中引导、分享菜单 12 渠道与 aria-expanded、 高亮计数一致性、高亮不越界到顶部栏、滚动联动与进度条、窄屏抽屉遮罩、四页零脚本报错。 当前 17 / 17。

它抓到过一个静态检查发现不了的问题：断言「高亮计数 == 正文 <mark> 数」 时报 46 对 43 —— 查下来是断言写窄了，脚本有意把 hero 与页脚也算作正文范围。 修的是断言，不是脚本。

口径差异
